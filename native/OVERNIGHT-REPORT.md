## 一、持久化差分硬盘

### 已完成

- 底盘以只读句柄打开，客体写入只追加到独立 `.cow` 文件。
- 关闭程序后再次打开同一底盘和差分盘，保留上次写入。
- 底盘完整 SHA256 绑定、逐条 CRC32 校验；底盘不匹配、记录损坏、尾部截断均明确报错。
- GUI 支持打开差分盘、记忆底盘/差分盘组合、关机后确认丢弃差分写入。
- 可在完全关闭占用它的程序后复制差分文件，保存磁盘检查点。

### 推荐使用方法

在仓库根目录执行，使用新的差分文件名：

```powershell
.\native\run.ps1 -Cpu 486 -StableTiming -FullSpeed `
  -HardDisk 'D:\ASM\Windows98_new.img' `
  -Overlay 'D:\ASM\Windows98-experiment.cow'
```

GUI 仍以关机状态打开，再选择 **Machine > Boot / restart from C:**。
也可以用 **Disks > Open C: with overlay** 选择底盘和差分文件。

**普通 Open C: hard disk、不带 `-Overlay` 的显式硬盘启动仍是原有直接写入模式。**
以后实验时应明确选用差分模式；底盘必须保持不变。

需要放弃本次实验时，先正常关机，再用 GUI 的 **Discard overlay writes**。
也可关闭占用它的窗口后执行：

```powershell
.\native\build\asm86-native.exe `
  --hard 'D:\ASM\Windows98_new.img' `
  --overlay 'D:\ASM\Windows98-experiment.cow' --discard-overlay
```

这会删除差分中的全部客体写入，不会向底盘合并。

### 验证

- DOS 写入文件，退出整个进程，再次冷启动后读取成功。
- Windows 98 通过差分盘进入桌面、接受输入、正常 APM 关机。
- 原始底盘与工作底盘 SHA256 不变。
- 单元测试覆盖重复扇区写入、持久化、错误底盘、损坏/截断、丢弃后重用及写入句柄保护。

## 二、已安装系统自动回归

新增 [test-os.ps1](test-os.ps1) 和测试辅助程序 [test-os-disk.cpp](test-os-disk.cpp)。

每个系统使用独立底盘副本及差分盘，执行写入与再次冷启动；
通过真正读取 FAT 文件内容验证持久化，避免把“键盘输入已经回显”误当成文件写入成功。
Windows 95/98 还必须执行正常关机并产生实际 APM 断电请求，不能只靠等待时间推断关机。

脚本有超时、独立进程退出码、失败截图、日志、JSON 结果和源盘/底盘哈希检查；
只终止自身启动的超时进程。成功后清理自身工作盘，失败时保留诊断材料。

### 两轮正式回归结果

两轮均为每个系统两次独立启动，共 16 次系统启动：

| 系统 / 使用的源盘 | 回归工具版本 | 最终整合版本 | 检查内容 |
|---|---:|---:|---|
| DOS 6.22 / `D:\ASM\DOS.img` | 通过，16.33 秒 | 通过，16.60 秒 | 冷启动、写入、再次冷启动、文件持久化 |
| Windows 3.1 / [win31-386.img](win31-386.img) | 通过，94.57 秒 | 通过，94.35 秒 | 386 增强模式启动、正常退出、文件持久化 |
| Windows 95 / `D:\ASM\Windows95.img` | 通过，173.77 秒 | 通过，173.70 秒 | 图形启动、命令输入、文件持久化、正常 APM 关机 |
| Windows 98 / `D:\ASM\Windows98_new.img` | 通过，184.50 秒 | 通过，184.95 秒 | 图形启动、命令输入、文件持久化、正常 APM 关机 |

时间为整个系统测试流程的宿主耗时，包含固定等待和两次启动，**不是启动性能排行榜**。
Windows 97、其他 Windows 98 镜像只做了原盘完整性检查，不宣称逐个启动验证。

运行示例：

```powershell
.\native\test-os.ps1 `
  -DosImage 'D:\ASM\DOS.img' `
  -Win31Image '.\native\win31-386.img' `
  -Win95Image 'D:\ASM\Windows95.img' `
  -Win98Image 'D:\ASM\Windows98_new.img'
```

默认生成全新的临时结果目录；也可指定不存在的 `-OutputDirectory`。
`-KeepDisks` 保留成功后的工作盘，`-TimeoutSeconds` 调整单个进程超时。
当前 Windows 98 源盘存在 `vnetbios.vxd` 启动提示，脚本按已知提示处理；
无此提示的其他镜像应传 `-Win98Warning ''`。本轮没有修改源盘来清除此提示。

### 自动化过程中处理的问题

早期尝试从 Windows 95 的 DOS 窗口切换全屏，以及从 DOS 批处理内部触发关机，
受窗口状态和“DOS 程序仍未退出”影响，不能作为稳定断言。
最终改为普通命令输入、标准 Start 菜单关机及独立 FAT 校验，不把这些自动化问题误报成模拟器故障。
错误状态断言、等待超时、错误预期文件内容等负向检查也确认会返回失败。

## 三、大容量硬盘

### 已完成

- 原生 `Disk` 上限提高到 **32 GiB**；保留原来小盘的完整柱面校验。
- 大盘采用稀疏原始文件，不先分配整盘内存或写满 32 GiB；文件系统不支持稀疏文件时明确报错。
- BIOS CHS 翻译；实现 EDD `41h / 42h / 43h / 44h / 47h / 48h`。
- 保持 ATA LBA28 的完整容量与高位地址。
- 检查 DAP、扇区数量、64 KiB 边界和 64 位 LBA 越界；写入前暂存客体源数据，
  防止分页访问错误导致部分磁盘写入。

GUI 可新建 **31.5 / 126 / 504 MiB / 2 / 8 / 32 GiB** 硬盘。
命令行单位为 MiB：

```powershell
.\native\build\asm86-native.exe --create-hard 'D:\ASM\new-1g.img' 1024 --cpu 486
```

可选容量为 `31.5 / 126 / 504 / 1024 / 2048 / 8192 / 32768`，不覆盖已有文件。
新盘为空白盘，仍需在客体中分区、格式化和安装系统。

### 实际验证到哪里

1. **真实 DOS 6.22：1 GiB。** 在客体内用 FDISK 创建约 1024 MiB 主分区，
   执行 `FORMAT /U /S`，输出 `System transferred`，总文件系统空间为
   `1,073,168,384` 字节；完全独立地从该硬盘冷启动，读回 `LARGE-DISK-PERSIST-OK`。
   最终发布候选再次执行该冷启动检查，通过。
2. **32 GiB：原生单元/集成测试。** 验证最后一个扇区、ATA 高位 LBA、
   IDENTIFY 容量、EDD 参数和传输、越界及分页缓冲区异常。
3. **真实命令行创建。** 1 GiB 为 `1,073,741,824` 字节，32 GiB 为
   `34,359,738,368` 字节，均确认有 SparseFile 属性；已有目标的哨兵字节未被覆盖，
   无效容量返回失败且不创建文件。

**32 GiB 是虚拟硬盘容量上限，不是 DOS 6.22 的 FAT16 分区上限。**
DOS 6.22 应使用约 2 GiB 以内的 FAT16 分区。
本轮没有在多 GiB FAT32 分区上重新安装 Windows 95/98，不能把 32 GiB 扇区测试称为该安装场景已经通过。

## 四、暂停、状态显示与操作保护

- **Machine > Pause / Resume**：冻结 CPU 和设备虚拟时间，释放按键/鼠标；
  恢复时重置宿主计时基准，不补跑暂停的时长。
- 标题约每秒显示客体虚拟运行秒数、按宿主时间测得的 MIPS、
  最近采样区间的 C: 读写扇区数；暂停/关机显示零吞吐。
- 磁盘活动不包含底盘 SHA256 或差分索引扫描；状态采样不放进逐指令/逐帧热路径。
- 开机（包括暂停）时重启、强制断电、关闭窗口均需要确认，默认 **No**。
- 暂停不是关机：不能借暂停更换 CPU、硬盘或丢弃差分写入。
- 正常 APM 关机后可直接关闭窗口；仍应优先在 Windows 内正常关机。

GUI 自动测试覆盖暂停时钟冻结、恢复不追赶、输入释放、MIPS/磁盘统计、
取消危险操作时状态不变、确认关闭、关机后差分丢弃与取消。

## 尚未提供的能力

- 差分盘不是 RAM/CPU/设备状态快照；没有在线整机存档、自动合并、压缩、链式差分盘或截断日志自动恢复。
- 强制断电即使使用差分盘，也仍可能损坏差分中的客体文件系统；它保护的是底盘，而非保证所有未保存数据。
- [image.h](image.h) 的 FAT12/FAT16 工具和 OS 文件校验器仍限制为 **504 MiB**，
  因为现有映像工具会将整盘加载到内存；没有跟随原生 Disk 盲目提高上限。
- 没有新增 LBA48、GPT、SVGA、声卡或网卡；没有宣称完成 32 GiB Windows/FAT32 安装验证。

后续可优先做多 GiB FAT32 Windows 98 安装实测，再按需要选择 SVGA 或声卡，
不必为了本轮成果立即升级 CPU 架构。
