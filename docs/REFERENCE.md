# AsmPerfect 86 参考手册

本手册列出这台虚拟 PC 已经实现的全部功能：CPU 指令、中断向量、BIOS、DOS、显卡、鼠标、外围芯片和内存布局。写程序或运行旧的 DOS 程序时，可以用它查"这个功能有没有、行为是否和真机一样"。

内容以源代码为准（对应版本 0.16）。没有列出的功能就是没有实现：程序调用时，"消息"页会提示一次，然后按下面"未实现时的行为"一节处理。

## 1. 虚拟机概况

| 部件 | 实现 |
|---|---|
| CPU | 8088 档是 8086/8088（用 SingleStepTests/8088 真机测试集验证）；286 档是 80286（见 2.3、2.4）；386 档是 80386：32 位寄存器和指令、32 位保护模式、分页、虚拟 8086 模式（见 2.5，实模式指令用 SingleStepTests/80386 真机测试集验证）；486 档是不带浮点单元的 80486（486SX）：386 再加 486 的指令、EFLAGS 的 AC/ID 位、CPUID、CR0.WP（见 2.6） |
| 速度 | 8088 4.77MHz、286 12MHz、386 33MHz、486 66MHz 四档 |
| 内存 | 640KB 常规内存；286/386/486 档另有扩展内存，共 16MB（A20 门见 9.5） |
| 协处理器 | 没有（INT 11h 报告无 8087；8087 指令被跳过，见 2.7） |
| 显卡 | VGA：文本模式、CGA 图形模式、EGA/VGA 16 色平面模式、VGA 256 色模式 |
| 外设 | IDE 第一通道上的 ATA 硬盘（11.4）、软驱控制器 82077（11.3）、IDE 第二通道上的 ATAPI 光驱（11.2）、两片 8259 中断控制器（主片、从片）、8253 定时器、两片 8237 DMA 控制器、键盘控制器、PC 喇叭、CMOS 实时钟（含 IRQ8 中断）、两个 8250 串口、鼠标 |
| 磁盘 | 两种：① 模拟 DOS 用的"文件"虚拟磁盘（只有根目录，文件读写可以模拟磁盘耗时）；② 磁盘映像：软驱 A:、B:，硬盘 C:、D:，光驱，通过 INT 13h 按扇区读写，也有真的软驱控制器、IDE 控制器和 ATAPI 光驱（给 Windows 95 这样的 32 位驱动用）；可以从软盘、硬盘、可启动光盘启动真的 DOS 和 Windows（见第 11 节）；D: 还可以放光盘映像（.iso），变成只读硬盘（见 11.1） |
| BIOS / DOS | 用 JavaScript 实现（"高层模拟"）。中断向量指向 F000 段里的小段桩代码，桩代码里的陷阱指令 `F1 nn` 把控制交给 JavaScript |

虚拟时间以 8253 的时钟为单位（1,193,182 Hz）。"原机速度"下，虚拟时间与真实时间同步，延时、时钟中断、波特率和声音都和原机一致。

## 2. CPU 指令

### 2.1 全部 8086 指令

| 类别 | 指令 |
|---|---|
| 数据传送 | `MOV` `PUSH` `POP` `XCHG` `XLAT` `LEA` `LDS` `LES` `LAHF` `SAHF` `PUSHF` `POPF` `IN` `OUT` |
| 算术 | `ADD` `ADC` `SUB` `SBB` `CMP` `INC` `DEC` `NEG` `MUL` `IMUL` `DIV` `IDIV` `CBW` `CWD` |
| 十进制调整 | `DAA` `DAS` `AAA` `AAS` `AAM` `AAD`（`AAM`/`AAD` 可以带任意除数/乘数，例如 `D4 10`） |
| 逻辑 | `AND` `OR` `XOR` `NOT` `TEST` |
| 移位 | `SHL`/`SAL` `SHR` `SAR` `ROL` `ROR` `RCL` `RCR`（移 1 位或移 `CL` 位） |
| 串操作 | `MOVS` `CMPS` `SCAS` `LODS` `STOS`（字节和字），前缀 `REP` `REPE`/`REPZ` `REPNE`/`REPNZ`，可以加段超越；串操作执行中可以被中断，返回后继续 |
| 转移 | `JMP`（短、近、远、间接）、`CALL`（近、远、间接）、`RET`/`RETF`（可带弹出字节数）、全部 16 个条件跳转、`LOOP` `LOOPE` `LOOPNE` `JCXZ` |
| 中断 | `INT n` `INT 3` `INTO` `IRET` |
| 标志 | `CLC` `STC` `CMC` `CLD` `STD` `CLI` `STI` |
| 其他 | `HLT` `WAIT`（无操作）`NOP` `LOCK`（无操作）、段超越前缀 `ES:` `CS:` `SS:` `DS:` |

细节和真机一致：

- 标志位的计算（包括 `AF`、`PF`，以及移位、乘除法之后"未定义"标志的实际取值）按真 8088 的结果。
- `DIV`/`IDIV` 除数为 0 或商溢出时产生 0 号中断。
- `MOV SS, …` 和 `POP SS` 之后的那一条指令执行完之前不响应中断；`STI` 之后也延迟一条指令才开中断。
- 单步标志 `TF` 置位时，每条指令执行完产生 1 号中断。
- `HLT` 停机，等到有硬件中断才继续。

### 2.2 未公开的 8086 指令

这些操作码在 Intel 手册里没有，但真 8086/8088 会执行，模拟器也照做：

| 操作码 | 在 8086 上的行为 |
|---|---|
| `0F` | `POP CS` |
| `60`~`6F` | 和 `70`~`7F` 相同（条件跳转） |
| `C0`、`C1` | 和 `C2`、`C3` 相同（`RET`） |
| `C8`、`C9` | 和 `CA`、`CB` 相同（`RETF`） |
| `D6` | `SALC`：`CF=1` 时 `AL=FFh`，否则 `AL=0` |
| `F1` | 和 `F0` 相同（`LOCK` 前缀）。**例外**：在 F000 段里，`F1 nn` 是模拟器的陷阱指令，见 4.2 |
| `8F /1`~`/7`、`FE /2`~`/7`、`FF /7` 等 | 按真机的别名执行 |

反汇编页把这些指令标成橙色。

### 2.3 选 286/386 档时：和 8086 不同的地方

选 286 时 CPU 是 **80286**，选 386 时是 **80386**（386 在 286 的基础上多了 32 位的部分，见 2.5），选 486 时是 **80486**（见 2.6）。实模式下和 8088 不同的地方：

| 项目 | 8088 档 | 286/386 档 |
|---|---|---|
| 186/286 的新指令 | 没有（这些操作码按 2.2 的 8086 含义执行） | `PUSHA` `POPA` `PUSH 立即数` `IMUL r16,r/m16,立即数` `移位 r/m,立即数` `ENTER` `LEAVE` `BOUND` `INSB/INSW` `OUTSB/OUTSW`（可加 REP） |
| `0F` 开头的指令 | `0F` 是 `POP CS` | `SMSW`（286 读出 FFF0h）、`LMSW`、`SGDT` `SIDT` `LGDT` `LIDT`、`CLTS`、`LOADALL`（只有 286）；保护模式下还有 `SLDT` `STR` `LLDT` `LTR` `VERR` `VERW` `LAR` `LSL`（实模式下这些产生 6 号中断）；386 的指令见 2.5，286 上产生 6 号中断 |
| 无效操作码 | 都有某种含义（见 2.2） | 6 号中断，返回地址指向这条指令 |
| 标志寄存器位 12~15 | 恒为 1 | 恒为 0（程序据此判断是 8086 还是 286） |
| `PUSH SP` | 压入减 2 之后的 SP | 压入减 2 之前的 SP |
| 用 `CL` 或立即数移位 | 按全部 8 位计数 | 只取低 5 位 |
| 移位指令的 `/6` | 未公开的 SETMO | `SHL` 的别名 |
| 除法出错（0 号中断） | 返回地址指向下一条指令 | 返回地址指向出错的那条指令 |

### 2.4 286 保护模式

选 286/386 时完整模拟 80286 的保护模式（16 位；386 的扩展见 2.5）：

| 项目 | 说明 |
|---|---|
| 地址空间 | 24 位，16MB 内存（1MB 以上是 15MB 扩展内存）；第 20 位受 A20 门控制（见 9.5），关闭时和 8086 一样回绕 |
| 进入 | `LMSW` 把 PE 位置 1。286 不能用 LMSW 退出，要靠复位 CPU 回到实模式（见 9.5） |
| 描述符 | GDT、LDT、IDT；段描述符（代码、数据、向下扩展）、TSS、LDT、调用门、任务门、中断门、陷阱门；装入段寄存器时检查类型、特权级、存在位，并设置"已访问"位 |
| 访问检查 | 每次访问内存都检查段界限和读写权限；越界或写只读段产生 #GP（堆栈段是 #SS） |
| 特权级 | 0~3 环。经调用门调用更高特权级时从 TSS 取新堆栈并复制参数；RETF、IRET 返回外层时弹出外层的 SS:SP，并清掉外层不能用的数据段寄存器 |
| 中断和异常 | 经 IDT 的门进入，可能换特权级和堆栈；异常压入错误码；INT 指令检查门的 DPL；中断门关中断，陷阱门不关 |
| 任务切换 | JMP、CALL、INT 到 TSS 或任务门，IRET 在 NT 置位时返回前一个任务；保存和装入 44 字节的 286 TSS，设置忙位和 MSW 的 TS 位 |
| 特权指令 | CPL 不为 0 时 `HLT` `LGDT` `LIDT` `LLDT` `LTR` `LMSW` `CLTS` 产生 #GP；CPL 大于 IOPL 时 `IN` `OUT` `INS` `OUTS` `CLI` `STI` 产生 #GP；POPF、IRET 按 CPL 和 IOPL 决定能不能改 IOPL 和 IF |
| 出错的处理 | 异常时退回到指令开头再进入处理程序；处理异常时又出错是双重错误（#DF），再出错就"停机"，由主板复位 CPU（见 9.5） |
| `LOADALL` | 286 的未公开指令：从物理地址 800h 起装入全部寄存器和段描述符缓存。HIMEM.SYS 在 286 上用它访问扩展内存 |

已验证：MS-DOS 6.22 的 HIMEM.SYS 3.10（15MB XMS 内存，`DOS=HIGH` 把 DOS 放进 HMA）；Windows 3.0 的**标准模式**（`WIN /S`，运行到 Program Manager，"关于"里显示 Standard Mode）；**Windows 3.1** 的安装（6 张 1.44MB 软盘）和运行（"关于"里显示 Standard Mode，可用内存 13,395KB）。

进入或离开保护模式的过程不会被"后退"完整撤销（段描述符缓存不在历史记录里）。

汇编器只接受 8086 指令。反汇编页按所选 CPU 的含义显示这些操作码。

### 2.5 386

选 386 时 CPU 是 **80386**：

| 项目 | 说明 |
|---|---|
| 寄存器 | 32 位的 EAX EBX ECX EDX ESI EDI EBP ESP、EIP、EFLAGS；新的段寄存器 FS、GS；控制寄存器 CR0（PE、MP、EM、TS、PG 位）、CR2、CR3；调试寄存器 DR0~DR7 和测试寄存器 TR6、TR7（只能读写，不产生调试异常）。寄存器页上多一行 32 位寄存器 |
| 前缀 | `66h` 改变操作数大小（16 ↔ 32 位），`67h` 改变地址大小，`64h` `65h` 是 FS、GS 段超越 |
| 32 位寻址 | `[基址 + 变址 × 1/2/4/8 + 位移]`（SIB 字节），任何通用寄存器都能作基址和变址；以 ESP、EBP 为基址时默认用 SS |
| 新指令 | `MOVZX` `MOVSX`、`BT` `BTS` `BTR` `BTC`、`BSF` `BSR`、`SHLD` `SHRD`、`SETcc`、`IMUL r,r/m`、16/32 位位移的条件跳转、`LSS` `LFS` `LGS`、`PUSH/POP FS/GS`、`CWDE` `CDQ`、`JECXZ`、`MOV` 控制/调试/测试寄存器；串指令、LOOP、PUSHA 等都有 32 位的形式 |
| 实模式 | 和 286 一样，但会检查段界限：访问超过偏移 FFFFh 的字或双字产生 #GP（堆栈是 #SS），不再在段内回绕。从保护模式回来时保留段描述符缓存里的基址和界限，所以可以用"unreal 模式"在实模式下访问 4GB；`MOV CR0` 可以清掉 PE 回到实模式，不用复位 CPU |
| 32 位保护模式 | 段描述符的 32 位基址、20 位界限和粒度（G 位，按 4KB 计）、D/B 位（32 位代码段、32 位堆栈）；386 的 32 位调用门、中断门、陷阱门（压栈 32 位）；104 字节的 32 位 TSS（含 CR3、FS、GS），I/O 许可位图（CPL 大于 IOPL 时按位图决定能不能访问端口） |
| 分页 | CR0 的 PG 位打开后，线性地址经 CR3 指向的页目录和页表（4KB 一页）换成物理地址；检查存在位、用户/系统位和读写位，设置已访问位和"脏"位；不合规时产生 14 号异常 #PF（错误码，CR2 = 出错的地址）。有 TLB，写 CR3 时清空 |
| 虚拟 8086 模式 | EFLAGS 的 VM 位（IRETD、任务切换进入）：CPL 3，段按实模式算；`INT n`、`CLI` `STI` `PUSHF` `POPF` `IRET` 在 IOPL < 3 时产生 #GP 交给监控程序；中断时从 0 级堆栈进入，压入 GS FS DS ES。BIOS 陷阱在虚拟 8086 模式下照样工作；分页打开时 BIOS 读写内存（例如 INT 13h 的缓冲区）也经过页表。已用 Windows 3.1 的 386 增强模式验证 |
| LOCK 前缀 | 只能用在读-改-写内存的指令上，否则 6 号中断（和真 386 一样） |
| 协处理器 | CR0 的 EM 或 TS 置 1 时，ESC 指令产生 7 号中断 #NM（交给操作系统去模拟），否则跳过 |
| 内存 | 16MB；32 位地址空间里 16MB 以上没有内存（读出 FFh） |

**验证**：实模式下的全部指令（含 66h/67h 前缀的组合）用 SingleStepTests/80386 真机测试集（386EX 上录下的 1,758,699 个用例）检查，除了 53 个"指令执行到一半出异常"的边角情况（例如 PUSHAD 压到一半栈越界时已经写进内存的部分）以外全部一致；Intel 手册说"未定义"的标志位不比较。真机 386 的几个怪癖也照样模拟了：SIB 没有变址但比例不为 0 时基址乘以比例；`AAA`/`AAS` 加减 6 作用在整个 AX 上；16 位 `SHLD`/`SHRD` 移位次数超过 16 时的结果；16 位堆栈上 `POPAD` 把弹出值的高 16 位放进 ESP。保护模式、分页用 tests/cpu386.test.ts 里手写的机器码检查。已用真软件验证：MS-DOS 6.22 的 HIMEM.SYS（在 386 上用 32 位指令测试扩展内存）、Windows 3.1 的标准模式、**Windows 3.1 的 386 增强模式**（在 386 档上安装后，`WIN` 进入增强模式，运行到 Program Manager）。

### 2.6 486

选 486 时 CPU 是不带浮点单元的 **80486**（相当于 486SX），在 386（2.5）的基础上：

| 项目 | 说明 |
|---|---|
| 新指令 | `BSWAP r32`（字节顺序反过来）、`XADD`（交换并相加）、`CMPXCHG`（累加器等于目标时目标 = 源、ZF = 1，否则累加器 = 目标、ZF = 0；不相等时也把原值写回目标，和真的 486 一样）、`INVLPG`（作废一页的地址转换缓存）、`INVD` `WBINVD`（没有缓存，什么都不做）、`CPUID`（后期的 486 才有） |
| CPUID | 功能 0：最大功能号 1，厂商 `GenuineIntel`；功能 1：家族 4、型号 8（486DX4），特性位全是 0（没有浮点单元、没有 VME）。其他功能号返回 0 |
| EFLAGS | AC 位（位 18）能改：程序靠这一点区分 386 和 486；ID 位（位 21）能改：说明有 CPUID 指令 |
| CR0 | WP 位（位 16）：分页时内核态（0~2 级）写只读页也产生 14 号异常（386 上内核态可以写任何页）。Linux、Windows NT 靠它做"写时复制"。AM、NE、CD、NW 位可以读写 |
| 没有的 | 浮点单元（ESC 指令和 386 一样，见 2.7）；对齐检查（CR0.AM 和 EFLAGS.AC 都置 1 时 3 级的非对齐访问不产生 17 号异常）；486 的缓存、TLB 测试寄存器的新用法 |

386 档上这些新指令都是无效操作码（6 号中断），AC、ID 位改不动。Windows XP 的安装程序在 486 档上通过了"需要 80486"的检查，接着要求奔腾的 CMPXCHG8B 指令。验证：tests/cpu486.test.ts、tests/cpu386.test.ts（CR0.WP）。没有现成的 486 真机测试集。

### 2.7 8087 浮点指令

没有协处理器。`D8`~`DF` 开头的 ESC 指令只读完操作数就跳过，不做任何运算；`WAIT`（`9B`）是空操作。286/386 上 CR0（MSW）的 EM 或 TS 位为 1 时，ESC 指令产生 7 号中断（`WAIT` 在 MP 和 TS 都为 1 时产生），让操作系统去模拟。

- Turbo Pascal（`{$N+}`，默认 `{$E+}`）、Turbo C 等编译的程序会检测到"没有 8087"，改用自带的软件仿真（`INT 34h`~`3Eh`），运算结果正确。
- 直接使用 8087 指令的程序（Turbo Pascal 的 `{$E-}`，或者手写 `FLD` 的汇编程序）结果会是错的。

## 3. 内存布局

| 地址 | 内容 |
|---|---|
| `0000:0000`~`03FF` | 中断向量表（256 项，见第 4 节） |
| `0040:0000`~`00FF` | BIOS 数据区（见下表） |
| `0050:0100` | 一个字：第一个内存控制块（MCB）的段地址（`INT 21h AH=52h` 返回 `ES:BX`，`ES:[BX-2]` 就是它） |
| 程序前面 | 环境变量块的 MCB 和环境变量块（256 字节） |
| `0FF0:0000` | 程序的 PSP（汇编出来的程序和 EXE 都从这里装起；EXE/COM 映像从 `1000:0000` 开始） |
| … ~ `9FFF:000F` | 程序和空闲内存，用 MCB 链管理，到 640KB 为止 |
| `A000:0000`~`FFFF` | VGA 图形显存（模式 0Dh、0Eh、10h、12h、13h） |
| `C000:0000` | 显卡 BIOS 的 ROM 标志 `55 AA 40`（程序据此判断有 EGA/VGA 显卡） |
| `B000:0000` | 单色文本显存（模式 7） |
| `B800:0000` | 彩色文本显存、CGA 图形显存 |
| `F000:0000`~`07FF` | 中断 n 的桩代码在 `F000:n×8` |
| `F000:0800` | INT 8（时钟）的桩代码 |
| `F000:0810` | INT 9（键盘）的桩代码 |
| `F000:0840` | INT 10h 的桩代码：陷阱之后用 OUT 指令写 VGA 寄存器、调色板、DAC，需要时 REP STOSW 清屏（见 4.2） |
| `F000:0960`~`09FF` | INT 10h 桩代码用的标志、VGA 寄存器表、调色板、清屏参数 |
| `F000:0A00` | 8×8 字库，字符 128~255（`INT 1Fh` 指向这里） |
| `F000:0E00` | 鼠标事件回调的桩代码（中断 74h 指向这里） |

程序可以用 `INT 21h AH=25h` 或直接写向量表来挂接任何中断，和真机一样。

### 4.2 桩代码

每个中断的桩代码是 3 个字节：

```
F1 nn      陷阱：把中断号 nn 交给 JavaScript 处理
CF         IRET
```

`INT 16h` 和 `INT 21h` 的桩代码前面多一条 `FB`（`STI`），因为它们可能要等键盘输入，等待期间必须能响应键盘中断。需要等待时，CPU 停在陷阱指令上反复执行，期间照常响应硬件中断。

INT 8、INT 9 和鼠标回调是用真 8086 指令写的，因为它们要调用程序自己的代码（`INT 1Ch` 或鼠标处理程序）：

```
INT 8：  F1 08         ; 滴答数加 1
         CD 1C         ; INT 1Ch
         50 B0 20 E6 20 58   ; PUSH AX / MOV AL,20h / OUT 20h,AL / POP AX
         CF            ; IRET

INT 9：  F1 09 50 B0 20 E6 20 58 CF

鼠标：   保存 AX BX CX DX SI DI BP DS ES
         F1 74         ; 装入事件掩码、按键、坐标、移动量
         CALL FAR CS:[0E20h]
         恢复寄存器
         F1 75         ; 回调结束
         IRET
```

还有几处也必须用真的指令，因为 Windows 的 386 增强模式、Windows 95 在虚拟 8086 模式里调用 BIOS 时，靠截获端口读写知道 BIOS 做了什么：

- **INT 10h**（`F000:0840`）：陷阱切换模式后，用 OUT 指令把这个模式的 VGA 寄存器、调色板和 DAC 写到端口上，再用 REP STOSW 清屏（src/machine/vgarom.ts）。
- **INT 13h**（`F000:1400`）：硬盘（80h、81h）的读、写、校验扇区和真的 AT BIOS 一样，算出 LBA，写 IDE 控制器的任务文件寄存器和命令，等 DRQ，从数据端口读写 256 个字（src/machine/diskrom.ts，用本项目的汇编器在开机时汇编）。Windows 95 的 32 位 IDE 驱动会检查 BIOS 是否经过这些端口。
- **硬件中断的默认处理**（`F000:1600` 起，每个 16 字节）：需要时先进陷阱，再 `PUSH AX / MOV AL,20h / (OUT 0A0h,AL) / OUT 20h,AL / POP AX / IRET`。Windows 把中断送进虚拟 8086 模式的 BIOS 处理时，要截获到 EOI 才重新打开这个中断。
- **INT 9** 先用 `IN AL,60h` 真的读一次键盘端口。

反汇编页把陷阱指令显示为 `[INT nn 的功能由模拟器实现]`。

## 5. BIOS 功能

调用约定和 IBM PC BIOS 相同。表中"返回"一栏没写的寄存器保持不变。

### 5.1 INT 10h 显示

| AH | 功能 | 说明 |
|---|---|---|
| 00h | 设置显示模式 | AL = 模式（见第 8 节）；AL 的位 7 为 1 时不清屏。不支持的模式：提示一次，保持原来的模式。和真的 VGA BIOS 一样装入这个模式的全部寄存器（定序器、CRTC、图形控制器、属性控制器、杂项输出，程序可以读回来）；切换后 ROM 里的桩代码还会用 OUT 指令把这些值写一遍，这样 Windows 386 增强模式的显卡驱动（它靠截获端口跟踪显卡状态）才知道模式变了 |
| 01h | 设置光标形状 | CH/CL = 起始/结束扫描线（存在 BDA 60h） |
| 02h | 设置光标位置 | DH = 行，DL = 列（只有第 0 页） |
| 03h | 读光标位置和形状 | 返回 DH/DL = 行/列，CX = 形状 |
| 05h | 选择显示页 | 忽略（只有第 0 页） |
| 06h / 07h | 窗口上卷 / 下卷 | AL = 行数（0 = 清除窗口），BH = 填充属性（图形模式下是颜色），CH/CL 左上角，DH/DL 右下角 |
| 08h | 读光标处的字符和属性 | 返回 AL = 字符，AH = 属性；图形模式下返回 0 |
| 09h | 写字符和属性 | AL = 字符，BL = 属性（图形模式下是颜色；位 7 为 1 时与原像素异或，13h 模式除外），CX = 次数；光标不动 |
| 0Ah | 只写字符 | 同上，不改属性 |
| 0Bh | CGA 调色板 | BH = 0：BL = 背景/边框色；BH = 1：BL = 调色板号 |
| 0Ch | 写像素 | AL = 颜色（位 7 为 1 时异或，13h 模式除外），CX = x，DX = y |
| 0Dh | 读像素 | CX = x，DX = y；返回 AL = 颜色 |
| 0Eh | 电传方式输出字符 | AL = 字符；处理回车、换行、退格、响铃，到底部自动上卷；图形模式下 BL = 颜色 |
| 0Fh | 读当前模式 | 返回 AL = 模式，AH = 每行字符数，BH = 0 |
| 10h | 调色板 | 见下表 |
| 11h | 字库 | AL = 30h：返回 ES:BP = 8×8 字库（BH = 4 时是后 128 个字符），CX = 字符高度，DL = 行数 − 1；其他子功能忽略 |
| 12h | 取 EGA/VGA 信息 | BL = 10h：返回 BX = 0003h（彩色、256KB），CX = 0009h |
| 13h | 写字符串 | ES:BP = 字符串，CX = 长度，DH/DL = 起始行/列，BL = 属性；AL 位 0：写完后移动光标；位 1：字符串里字符和属性交替 |
| 1Ah | 显示组合 | AL = 0：返回 AL = 1Ah，BX = 0008h（VGA 彩色） |
| 1Bh、EFh、FEh | | 当作"不支持"，直接返回 |

| 01h | 设置边框色：BH |
| 02h | 设置全部 16 个调色板寄存器和边框色：ES:DX 指向 17 字节 |

| 07h | 读一个调色板寄存器：BL = 号；返回 BH |

### 5.2 INT 16h 键盘

| AH | 功能 | 说明 |
|---|---|---|
| 00h / 10h | 读键（等待） | 返回 AH = 扫描码，AL = ASCII |
| 01h / 11h | 查看有没有键（不取走） | 有键：ZF = 0，AX = 键值。没有键：ZF = 1，**AX 也会被设成缓冲区头部那个旧的键值**（与 IBM PC BIOS 相同，有些老程序依赖这一点） |
| 02h / 12h | 读 Shift 状态 | 返回 AL = BDA 17h |
| 03h | 设置重复速率 | 忽略 |
| 05h | 把一个键放进缓冲区 | CX = 扫描码:ASCII；返回 AL = 0（成功）或 1（缓冲区满） |

### 5.3 INT 1Ah 时钟

| AH | 功能 | 说明 |
|---|---|---|
| 00h | 读时钟滴答数 | 返回 CX:DX = 滴答数，AL = 过午夜标志（读后清零） |
| 02h | 读实时钟时间 | 返回 CH/CL/DH = 时/分/秒（BCD），DL = 0，CF = 0 |
| 04h | 读实时钟日期 | 返回 CH/CL = 世纪/年，DH/DL = 月/日（BCD），CF = 0 |
| 01h | 设置时钟滴答数 | CX:DX |
| 03h / 05h | 设置实时钟时间 / 日期 | 不改你电脑的时钟，直接返回成功 |
| 06h / 07h | 闹钟 | 不支持，CF = 1 |

时间和日期取自你电脑的当前时间。滴答数从程序开始时的 0 起，按虚拟时间增加。

### 5.4 INT 13h 磁盘

按扇区读写"虚拟磁盘"页里放入的磁盘映像。驱动器号 DL：00h = A:，01h = B:，80h = C:，81h = D:；从光驱启动（不模拟方式）时 E0h 是光驱（见本节末尾）。硬盘的 02h~04h 经 IDE 端口完成（见 4.2），其余功能和软盘的全部功能在 JavaScript 里完成。扇区位置用 CH = 柱面低 8 位，CL 位 6~7 = 柱面高 2 位、位 0~5 = 扇区号（从 1 开始），DH = 磁头。返回时 AH = 状态（0 表示成功），出错时 CF = 1；状态同时记在 BDA 41h（软盘）或 74h（硬盘）。

| AH | 功能 | 说明 |
|---|---|---|
| 00h / 0Dh | 复位 | |
| 01h | 读上次的状态 | 返回 AH |
| 02h | 读扇区 | AL = 扇区数，ES:BX = 缓冲区；返回 AL = 实际读的扇区数。超过一个磁道时接着读下一个磁头、柱面 |
| 03h | 写扇区 | 同上；写入的内容进入映像（并保存在浏览器里） |
| 04h | 校验扇区 | 只检查位置是否有效 |
| 05h | 格式化一个磁道 | 把这个磁道的全部扇区填成 F6h |
| 08h | 读驱动器参数 | 返回 CH/CL = 最大柱面号和每道扇区数，DH = 最大磁头号，DL = 驱动器个数；软驱还返回 BL = 类型（4 = 1.44MB），ES:DI = 软盘参数表。软驱里没有盘时按 1.44MB 驱动器回答 |
| 09h、0Ch、10h~14h | 初始化、寻道、就绪检查、校准、诊断 | 有盘时返回成功 |
| 15h | 读驱动器类型 | 软驱 AH = 2（支持换盘信号）；硬盘 AH = 3，CX:DX = 扇区总数；没有硬盘时 AH = 0 |
| 16h | 软盘是否换过 | 放入软盘后第一次调用返回 AH = 06h、CF = 1，之后返回 0 |
| 17h / 18h | 设置软盘类型 / 介质类型 | 返回成功（18h 还返回 ES:DI = 软盘参数表） |
| 41h~48h | 扩展磁盘功能（LBA） | 软盘、硬盘不支持，CF = 1（硬盘不超过 504MB，用 CHS 就够；提供扩展功能的话 Windows 95 可能改用它，绕过 IDE 端口）。光驱 E0h 支持，见下 |
| 4Bh | 光盘启动的状态 | 从光驱启动时（软盘模拟的 A:，或不模拟的 E0h）在 DS:SI 写 13h 字节的规格包 |

错误状态：01h 无效命令或没有这个硬盘，03h 写保护（光盘映像），04h 扇区找不到（位置超出范围），06h 换过软盘，80h 软驱里没有盘（超时）。

磁盘映像：
- 软盘支持 160KB、180KB、320KB、360KB、720KB、1.2MB、1.44MB、2.88MB 八种标准大小，按文件大小判断几何参数。
- 硬盘映像按分区表推测几何参数；没有分区表时用 16 磁头、每道 63 扇区。新建硬盘可选 32MB、64MB、128MB、504MB（最多 1024 个柱面）。
- 光盘映像（D:）用 255 磁头、每道 63 扇区，见 11.1。

**光驱 E0h**（只在"不模拟"方式从光驱启动时有）：41h（BX = 55AAh 时返回 AA55h、AH = 21h、CX = 1：支持按包读写）、42h（扩展读：DS:SI 是磁盘地址包，每块 2048 字节，直接从光盘映像读，数据还没从文件里读出来时等一会儿再执行）、43h（写：报告写保护）、48h（驱动器参数：每扇区 2048 字节、扇区总数）、4Bh、00h/01h/0Dh/44h/47h（返回成功）。

| 0Eh | 驱动程序版本 | 返回 AX = 0102h |


| 中断 | 说明 |
|---|---|
| 11h | 返回 AX = BDA 10h 的设备字（0041h，两个软驱） |
| 12h | 返回 AX = 640 |
| 14h | 串口 BIOS：AH = 00h / 03h 返回 AH = 60h、AL = 30h（发送器空、就绪）；AH = 01h / 02h 返回 AH = 80h（超时）。程序要收发串口数据，请直接操作 8250 |
| 15h | AT 系统服务：4Fh（键盘拦截）返回 CF = 1；88h 返回扩展内存的 KB 数（286/386 时 15360，8088 时 0）；87h 在扩展内存之间搬数据（ES:SI 指向的 GDT 第 2、3 项是源和目标，CX 个字；只在 286/386 时）；86h（等待）直接返回；90h、91h 返回成功；53h 是 APM 电源管理（见下）；其他功能（C0h 系统配置、24h 等）返回 AH = 86h、CF = 1（不支持） |
| 17h | 打印机：总是返回 AH = 90h（就绪），打印的字符丢弃 |
| 19h | 从原来的启动盘重新启动；运行普通程序时忽略 |
| 1Ch | 空的定时器钩子，每秒约 18.2 次由 INT 8 调用 |

## 6. DOS 功能（INT 21h）

模拟的是 DOS 5.0（`AH=30h` 返回 5.0）。出错时一律 CF = 1、AX = 错误码；成功时 CF = 0。

### 6.1 字符输入输出

| AH | 功能 | 说明 |
|---|---|---|
| 01h | 读键并回显 | 返回 AL = 字符（等待） |
| 02h | 显示字符 | DL = 字符 |
| 05h | 打印字符 | 忽略 |
| 06h | 直接控制台输入输出 | DL ≠ FFh：显示 DL。DL = FFh：有键时 ZF = 0、AL = 字符；没键时 ZF = 1、AL = 0（不等待） |
| 07h / 08h | 读键不回显 | 返回 AL = 字符（等待） |
| 09h | 显示字符串 | DS:DX 指向以 `$` 结束的字符串 |
| 0Ah | 行输入 | DS:DX 指向缓冲区：第 0 字节 = 最大长度，返回第 1 字节 = 实际长度，从第 2 字节起是字符，以回车结束；支持退格 |
| 0Bh | 检查有没有键 | 返回 AL = FFh（有）或 0 |
| 0Ch | 清空键盘缓冲区再执行 | AL = 01h、06h、07h、08h、0Ah 中的一个功能 |

### 6.2 文件（文件句柄）

| AH | 功能 | 说明 |
|---|---|---|
| 3Ch | 创建文件 | DS:DX = 文件名；返回 AX = 句柄（已存在则清空） |
| 3Dh | 打开文件 | DS:DX = 文件名，AL = 方式（0 读、1 写、2 读写）；返回 AX = 句柄 |
| 3Eh | 关闭文件 | BX = 句柄 |
| 3Fh | 读 | BX = 句柄，CX = 字节数，DS:DX = 缓冲区；返回 AX = 实际读到的字节数。句柄 0（标准输入）按行读键盘 |
| 40h | 写 | BX = 句柄，CX = 字节数，DS:DX = 数据；返回 AX = 写入字节数。CX = 0 时把文件截断在当前位置。句柄 1、2 输出到屏幕，3、4 丢弃 |
| 41h | 删除文件 | DS:DX = 文件名 |
| 42h | 移动读写位置 | BX = 句柄，CX:DX = 位移，AL = 0 从头、1 从当前、2 从末尾；返回 DX:AX = 新位置 |
| 43h | 读文件属性 | DS:DX = 文件名；返回 CX = 20h（存档） |
| 44h | IOCTL | AL = 0：读设备信息。句柄 0~2 返回 DX = 80D3h（字符设备），文件返回 DX = 0002h |
| 56h | 改名 | DS:DX = 旧名，ES:DI = 新名 |
| 57h | 文件日期时间 | BX = 句柄；AL = 0：返回 CX = 时间，DX = 日期（DOS 格式）。AL = 1：用 CX/DX 设置 |
| 5Bh | 创建新文件 | 同 3Ch，但文件已存在时出错（错误码 50h） |

- 文件句柄从 5 开始分配，最多同时打开 16 个（到句柄 20）。
- 文件名不区分大小写，可以带 `C:`、`\` 前缀，路径分隔符 `\` 和 `/` 都行。
- 文件时间：上传的文件用原文件的修改时间，程序写过的文件用写入的时间。
- 写入在关闭之前就会反映到"虚拟磁盘"页上。

### 6.3 查找文件和目录

| AH | 功能 | 说明 |
|---|---|---|
| 1Ah | 设置 DTA | DS:DX；程序开始时 DTA 在 PSP:0080 |
| 2Fh | 读 DTA | 返回 ES:BX |
| 4Eh | 查找第一个文件 | DS:DX = 文件名（可以带 `*`、`?`），CX = 属性。结果写进 DTA：15h 属性，16h 时间，18h 日期，1Ah 大小（双字），1Eh 文件名（以 0 结束）。CX = 08h 时只返回卷标 `ASM86` |
| 4Fh | 查找下一个 | 用 DTA 保留区（00h~14h）里保存的查找状态，和真 DOS 一样，程序可以同时进行多个查找 |
| 11h / 12h | 用 FCB 查找第一个 / 下一个 | DS:DX = FCB（可以是以 FFh 开头的扩展 FCB）；找到时 AL = 0，DTA 里是"驱动器号 + 32 字节目录项"；找不到 AL = FFh |
| 29h | 分析文件名到 FCB | DS:SI = 字符串，ES:DI = FCB，AL = 控制位；返回 AL = 0（无通配符）或 1（有），SI 指向分析结束处 |
| 39h / 3Ah | 建立 / 删除目录 | 不支持子目录，返回错误 |
| 3Bh | 改变当前目录 | 只有切换到根目录（`\`、`.`、空）能成功 |
| 47h | 读当前目录 | 返回空字符串（根目录） |
| 19h | 读当前驱动器 | 返回 AL = 2（C:） |
| 0Eh | 选择驱动器 | 返回 AL = 3（驱动器数） |
| 36h | 磁盘剩余空间 | 返回 AX = 8 扇区/簇，BX = 2000 空闲簇，CX = 512 字节/扇区，DX = 4000 总簇数（约 16MB 的盘，剩一半） |

通配符按 DOS 的 8.3 规则匹配（`*` 匹配到名字或扩展名的末尾）。名字不符合 8.3 格式的文件不会被列出。找不到或没有更多文件时返回错误码 12h（4Eh 在找不到路径时返回 03h）。

### 6.4 内存管理

| AH | 功能 | 说明 |
|---|---|---|
| 48h | 分配内存 | BX = 段落数；返回 AX = 段地址。失败时 BX = 最大可用块，错误码 8（内存不足）或 7（MCB 损坏） |
| 49h | 释放内存 | ES = 块的段地址 |
| 4Ah | 调整内存块大小 | ES = 块，BX = 新的段落数；失败时 BX = 最大可能的大小 |
| 52h | 取"表的表" | 返回 ES:BX，`ES:[BX-2]` 是第一个 MCB 的段地址（用来遍历 MCB 链） |

内存用标准的 MCB 链管理（每块前面一个 16 字节的控制块，`M`/`Z` 标记，记录拥有者 PSP 和程序名）。程序开始时拥有到 640KB 为止的全部内存，和 DOS 一样，要分配内存得先用 4Ah 缩小自己。

### 6.5 进程、中断向量、时间

| AH | 功能 | 说明 |
|---|---|---|
| 00h | 结束程序 | 返回码 0 |
| 4Ch | 结束程序 | AL = 返回码 |
| 31h | 驻留结束（TSR） | 当作普通结束处理，并提示 |
| 4Dh | 读上一个程序的返回码 | 返回 AX |
| 25h | 设置中断向量 | AL = 中断号，DS:DX = 处理程序 |
| 35h | 读中断向量 | AL = 中断号；返回 ES:BX |

| 2Dh | 设置时间 | 忽略，返回 AL = 0 |
| 30h | 读 DOS 版本 | 返回 AL = 5，AH = 0（DOS 5.0），BX = CX = 0 |

### 6.6 磁盘耗时

"串口"页勾选"DOS 文件操作消耗时间（模拟磁盘）"时（默认勾选）：

- 打开、创建、删除、改名约 3 毫秒，关闭约 2 毫秒，查找文件约 1~3 毫秒；
- 读写按扇区（512 字节）计算：不在缓冲区里的扇区每个约 0.5 毫秒，再加 0.5 毫秒；最近用过的 40 个扇区（相当于 `BUFFERS=40`）几乎不花时间。

等待期间 CPU 停在 `INT 21h` 里，硬件中断照常响应，和真 DOS 等磁盘时一样。

## 7. 鼠标驱动（INT 33h）

模拟 Microsoft 鼠标驱动 6.26，两键鼠标。坐标是驱动的"虚拟屏幕"坐标：水平 0~639；垂直方向在 200 行的模式（包括文本模式）里是 0~199，模式 10h 是 0~349，模式 12h 是 0~479。文本模式下每个字符占 8×8，320 宽的图形模式里 x 坐标是像素的 2 倍。

程序切换显示模式（INT 10h AH=00h）时，驱动和真的一样自动把活动范围改成新模式的虚拟屏幕大小。

从磁盘启动真 DOS 时，需要先运行 MOUSE.COM（见第 11 节），因为 DOS 启动时会把 INT 33h 改成 IRET。

函数 24h 报告的鼠标类型是"串口鼠标，IRQ 3"，和下面 COM2 上的串口鼠标一致。

### 7.1 COM2 上的串口鼠标

Windows 的鼠标驱动和当年的 DOS 鼠标驱动（MOUSE.COM、CTMOUSE 等）不用 INT 33h，而是直接操作鼠标硬件。为此 COM2（2F8h，IRQ3）上接了一只串口鼠标，按驱动设置的数据位数自动选择协议：

| 驱动把 COM2 设成 | 协议 | 说明 |
|---|---|---|
| 1200 bps，7 位数据 | Microsoft 鼠标 | DTR、RTS 都置 1（上电）后发出 `M`；每次移动或按键变化发 3 字节的数据包 |
| 1200 bps，8 位数据 | Mouse Systems 鼠标 | DTR 或 RTS 置 1 后开始工作；每次发 5 字节的数据包 |

鼠标的移动量来自网页上的鼠标。驱动在用串口鼠标时（程序自己画光标），单击 DOS 屏幕会"捕获"鼠标：浏览器的光标消失，移动量全部交给虚拟机，按 Esc 释放。

**Windows 3.1 使用鼠标**：在 Windows Setup 里把 Mouse 改成 **Microsoft, or IBM PS/2**，它的驱动会在 COM2 上找到 Microsoft 串口鼠标。

**Windows 3.0 使用鼠标**：Windows 安装程序检测不到串口鼠标。安装时在硬件列表里把 Mouse 改成 **Mouse Systems (or VisiOn) connected to COM2:**；已经装好的，在 Windows 的"Windows Setup"程序里用 Options → Change System Settings 修改。注意安装盘上的驱动程序是压缩过的，要由安装程序展开，不能直接复制。

| AX | 功能 | 说明 |
|---|---|---|
| 00h / 21h | 复位 / 软件复位 | 返回 AX = FFFFh（有鼠标），BX = 2（键数）；光标隐藏、移到中央 |
| 01h | 显示光标 | 显示计数加 1（到 0 时显示） |
| 02h | 隐藏光标 | 显示计数减 1 |
| 03h | 读位置和按键 | 返回 BX = 按键（位 0 左，位 1 右，位 2 中），CX = x，DX = y |
| 04h | 设置位置 | CX = x，DX = y |
| 05h | 读按下信息 | BX = 键号；返回 AX = 当前按键，BX = 上次读以来按下的次数，CX/DX = 最后一次按下的位置 |
| 06h | 读松开信息 | 同上，松开 |
| 07h / 08h | 设置水平 / 垂直范围 | CX = 最小值，DX = 最大值 |
| 09h | 设置图形光标形状 | BX/CX = 热点，ES:DX = 16 个字的屏幕掩码 + 16 个字的光标掩码 |
| 0Ah | 设置文本光标 | BX = 0：软件光标，CX = 屏幕掩码，DX = 光标掩码；BX = 1：硬件光标 |
| 0Bh | 读移动量 | 返回 CX/DX = 上次读以来水平/垂直移动的 mickey 数 |
| 0Ch | 设置事件处理程序 | CX = 事件掩码，ES:DX = 处理程序（远调用） |
| 0Fh | 设置 mickey/像素比 | CX = 水平（默认 8），DX = 垂直（默认 16） |
| 14h | 交换事件处理程序 | 设置新的，返回原来的 CX、ES:DX |
| 15h | 保存状态需要的大小 | 返回 BX = 64 |
| 16h / 17h | 保存 / 恢复状态 | 直接返回 |
| 1Ah / 1Bh | 设置 / 读灵敏度 | |
| 1Eh | 读显示页 | 返回 BX = 0 |
| 1Fh / 20h | 禁用 / 启用驱动 | |
| 24h | 读驱动版本 | 返回 BX = 0626h（6.26），CX = 0400h（PS/2 鼠标） |
| 26h | 读最大坐标 | 返回 CX/DX = 当前范围的最大值 |
| 10h、13h、1Ch、1Dh | 禁区、加速阈值、中断频率、显示页 | 忽略 |

**事件处理程序**（AX=0Ch）：事件掩码的位 0 移动，位 1/2 左键按下/松开，位 3/4 右键按下/松开，位 5/6 中键按下/松开。事件发生时驱动远调用处理程序，进入时 AX = 发生的事件，BX = 按键，CX/DX = 坐标，SI/DI = 移动量；处理程序用 `RETF` 返回。即使程序正在等键盘（`INT 16h`），事件也会送达。

**按键时间**：很快的一次点击（按下和松开几乎同时）也会保持至少约 30 毫秒虚拟时间，用轮询方式（AX=03h）的程序也能看到。

**光标**：文本模式和图形模式都画在屏幕上（叠加显示，不改显存）。

## 8. 显示模式与显卡

### 8.1 支持的模式

| 模式 | 类型 | 分辨率 | 颜色 | 显存 | 文字 |
|---|---|---|---|---|---|
| 00h / 01h | 文本 | 40×25 | 16 色 | B800 | |
| 02h / 03h | 文本 | 80×25 | 16 色 | B800 | 默认模式 |
| 07h | 文本（单色） | 80×25 | | B000 | |
| 04h / 05h | CGA 图形 | 320×200 | 4 色 | B800（偶数行在 0000h，奇数行在 2000h） | 40×25，8×8 |
| 06h | CGA 图形 | 640×200 | 2 色 | B800（同上） | 80×25，8×8 |
| 0Dh | EGA 图形 | 320×200 | 16 色 | A000，4 个平面，每行 40 字节 | 40×25，8×8 |
| 0Eh | EGA 图形 | 640×200 | 16 色 | A000，4 个平面，每行 80 字节 | 80×25，8×8 |
| 10h | EGA 图形 | 640×350 | 16 色（64 色中选） | A000，4 个平面，每行 80 字节 | 80×25，8×14 |
| 12h | VGA 图形 | 640×480 | 16 色（26 万色中选） | A000，4 个平面，每行 80 字节 | 80×30，8×16 |
| 13h | VGA 图形 | 320×200 | 256 色 | A000，每个像素一个字节 | 40×25，8×8 |

不支持的模式（例如 0Fh、11h，以及 VESA 高分辨率模式）调用时会提示，保持原来的模式。

文本模式的字形是浏览器里的等宽字体，按代码页 437 显示制表符和特殊字符；勾选"中文"后，像 UCDOS 那样把 GBK 编码显示成汉字（会自动识别西文制表符）。图形模式下 BIOS 写字使用内置的 8×8 点阵字库，14、16 点高的模式把它纵向放大。

### 8.2 文本模式显存

每个字符两个字节：字符码、属性。属性的位 0~3 是前景色，位 4~6 是背景色，位 7 是闪烁。光标位置除了 BIOS 以外，也可以直接写 CRT 控制器的 0Eh/0Fh 寄存器（端口 3D4h/3D5h）。

### 8.3 VGA 256 色（13h）

显存 A000:0000 起，每个像素一个字节（颜色号），一行 320 字节。颜色号经过 DAC 调色板（256 种颜色，每种红绿蓝各 6 位）变成实际颜色。开机调色板与真 VGA 相同：0~15 是 EGA 16 色，16~31 是灰度，32~247 是色环，248~255 是黑色。

### 8.4 EGA/VGA 16 色平面模式（0Dh、0Eh、10h、12h）

显存分成 4 个平面，每个平面 64KB；A000 段的一个字节地址对应 4 个平面里各一个字节，也就是 8 个像素。像素的颜色号由 4 个平面里的同一位拼成（平面 0 是最低位）。CPU 读写 A000 段时经过显卡的图形控制器，全部按真 VGA 模拟：

- **读**：每次读都把 4 个平面的字节装进锁存器。
  - 读模式 0：返回"读平面选择"寄存器指定的那个平面。
  - 读模式 1：和"颜色比较"寄存器比较，相同的像素位为 1（受"颜色无关"寄存器控制）。
- **写**：
  - 写模式 0：数据先循环右移，再按"允许置位/复位"决定每个平面用数据还是"置位/复位"的值。
  - 写模式 1：把锁存器原样写回（显存到显存的快速复制）。
  - 写模式 2：数据的低 4 位是颜色，展开到 4 个平面。
  - 写模式 3：循环移位后的数据和位屏蔽相与，作为新的位屏蔽，颜色取"置位/复位"。
  - 写模式 0、2、3 都要和锁存器做逻辑运算（替换、与、或、异或），再经过"位屏蔽"（屏蔽掉的位保留锁存器的值），最后只写"平面屏蔽"允许的平面。
- **颜色**：颜色号（0~15）先经过属性控制器的 16 个调色板寄存器，变成 6 位颜色值，再查 DAC。
  - 10h、12h 模式：DAC 的前 64 种是 EGA 的 64 色（rgbRGB），调色板寄存器的默认值是 0、1、2、3、4、5、14h、7、38h~3Fh。
  - 0Dh、0Eh 模式：调色板寄存器直接指向前 16 种 DAC 颜色。
  - 属性控制器的模式控制寄存器位 7 和颜色选择寄存器也会生效。

Turbo Pascal / Turbo C 的 BGI 驱动 `EGAVGA.BGI` 就是直接操作这些寄存器画图的，可以正常使用。

**没有模拟**：CRT 控制器的起始地址（翻页、硬件卷屏）、定序器的内存模式（Mode X 等非链式 256 色模式）、平面模式下的多个显示页。

### 8.5 CGA 调色板

模式 04h/05h 的 4 种颜色由端口 3D9h（或 INT 10h AH=0Bh）决定：位 0~3 背景色，位 4 高亮，位 5 选调色板（0：绿红棕，1：青品红白）。模式 05h 固定用青红白。模式 06h 是黑白。

### 9.1 8259 中断控制器

硬件中断的默认处理程序（IRQ2~7、IRQ8~15，鼠标的 IRQ12 除外）是 ROM 里的小段代码，用真的 OUT 指令发 EOI：Windows 增强模式把中断送进虚拟 8086 模式的 BIOS 处理时，要截获到 EOI 才重新打开这个中断。

和 AT 机一样两片：主片（端口 20h、21h，IRQ0~7，向量默认从 08h 开始）和接在主片 IRQ2 上的从片（端口 A0h、A1h，IRQ8~15，向量默认从 70h 开始），都可以用 ICW2 改。主片初始屏蔽字 B8h，即开放 IRQ0（时钟）、IRQ1（键盘）、IRQ2（级联）、IRQ6；从片初始全部屏蔽。程序要用串口中断时，需要自己清除 IRQ3/IRQ4 的屏蔽位，和真机一样。支持优先级、嵌套（ISR）、非特定和特定 EOI；从片的中断要给两片都发 EOI。

**IRQ8 实时钟**：CMOS 寄存器 B 的位 6 打开周期中断（频率由寄存器 A 的低 4 位决定，默认 1024Hz），位 4 打开每秒一次的更新结束中断；中断原因在寄存器 C 里，读出后清零，读之前不会再发下一次中断（和真的 MC146818 一样）。

**DMA 控制器**：两片 8237 和页寄存器。2 号通道真的传送数据（软驱控制器用，见 11.3）：按模式写内存、读内存或校验，地址递增或递减，计数到达终点时停止、在状态寄存器里记下，单次传送的通道随后被屏蔽，自动初始化的通道恢复基准值。其他通道只保存寄存器的值（能读回来）。DOS 下软盘、硬盘都由 BIOS 高层模拟，不经过 DMA。

### 9.2 8253 定时器

- 0 号通道：产生 IRQ0（INT 8）。默认计数 65536，约每秒 18.2 次；程序改计数值可以改变时钟中断频率。可以读当前计数值（包括锁存命令）。
- 1 号通道：只保存设置。
- 2 号通道：设置的频率用于 PC 喇叭（见端口 61h），用电脑的声卡发声。

### 9.3 键盘

在 DOS 屏幕上点一下，就可以直接用键盘输入。每个按键经过 IRQ1 → INT 9 → BIOS 键盘缓冲区；程序也可以挂接 INT 9，自己从端口 60h 读扫描码（按下、松开都有）。Shift、Ctrl、Alt 的状态记在 BDA 17h。同时按着 Ctrl、Alt 时按 Del，BIOS 热启动（0040:0072 写 1234h，从原来的启动盘重新启动；运行普通程序时只提示）。浏览器里按 Ctrl+Alt+Del 会被 Windows 系统截走，所以工具栏上有一个"Ctrl+Alt+Del"按钮，把这三个键依次送进虚拟机；程序自己挂接了 INT 9 的话（例如 Windows），会由程序处理。粘贴的文字会以一定间隔逐个送入。

### 9.4 8250 串口

两个 8250 串口：COM1（3F8h，IRQ4）、COM2（2F8h，IRQ3）。

| 偏移 | DLAB = 0 读 / 写 | DLAB = 1 |
|---|---|---|
| +0 | 接收缓冲 RBR / 发送保持 THR | 除数低字节 |
| +1 | 中断允许 IER | 除数高字节 |
| +2 | 中断识别 IIR（读） | |
| +3 | 线路控制 LCR（数据位、停止位、校验、DLAB） | |
| +4 | Modem 控制 MCR（DTR、RTS、OUT2、回环） | |
| +5 | 线路状态 LSR（数据就绪、溢出、帧错误、THR 空、发送器空） | |
| +6 | Modem 状态 MSR（CTS、DSR、RI、DCD 及其变化位） | |
| +7 | 暂存寄存器 SCR | |

- 发送一个字符的时间按波特率和帧格式（起始位 + 数据位 + 校验位 + 停止位）精确计算。
- 中断：接收数据、THR 空、线路状态、Modem 状态四种，`OUT2` 为 1 时才送到 8259。
- `MCR` 的回环位：发送的数据直接回到自己的接收端。
- 双机模式下两台机器的 COM1 用虚拟串口线连接，接线方式可选：全握手、部分握手、三线制。
- "串口芯片"选项：
  - "真实 8250"：写 THR 时上一个字节还没发出就会被覆盖，和真机一样；
  - "虚拟串口"：带发送缓冲和硬件流控，方便运行没检查 THR 的程序。
- 帧格式或波特率两端不一致时产生帧错误。
- "串口"页显示信号线状态和线路上的每个字节。

### 9.5 A20 门和复位 CPU（286/386）

**A20 门**：开机时关闭，地址超过 1MB 时回绕到 0（和 8086 一样）。打开的方法有三种：
- 键盘控制器命令 D1h 后往 60h 写输出端口，位 1 是 A20；
- 命令 DFh/DDh 打开/关闭；
- 端口 92h 的位 1。

HIMEM.SYS 就是这样打开 A20 的。

**复位 CPU** 的方法：键盘控制器命令 FEh、输出端口位 0 写 0、端口 92h 位 0 从 0 变 1，以及三重错误。

286 没有离开保护模式的指令，AT 机上的程序用复位 CPU 的办法回到实模式。BIOS 开机时先看 CMOS 的 0Fh 字节（关机原因），这里按 AT 机 BIOS 的做法处理：

| 0Fh | 处理 |
|---|---|
| 05h | 给中断控制器发 EOI，跳到 0040:0067 里的远地址 |
| 0Ah | 直接跳到 0040:0067 里的远地址 |
| 09h | "从 INT 15h 87h 返回"：0040:0067 里是 SS:SP，换到这个堆栈，弹出 DS、ES，再 POPA、IRET（Windows 3.0 标准模式用这种） |
| 其他 | 重新开机 |

复位时内存、A20 状态保持不变，CPU 回到实模式，0Fh 清零。

## 10. 程序的装载

### 10.1 汇编出来的程序

- EXE 格式（`.MODEL SMALL` 等）：PSP 在 `0FF0:0000`，代码从 `1000:0000` 起。开始时 DS = ES = PSP，CS:IP = `END` 指定的入口，SS:SP = 栈段（`.STACK` 的大小）。
- COM 格式（`ORG 100h`）：CS = DS = ES = SS = PSP 段，IP = 100h，SP = FFFEh，栈顶压一个字 0（`RET` 会跳到 PSP:0000 的 `INT 20h`）。
- 开始时标志寄存器为 F202h（IF = 1），通用寄存器全为 0。

### 10.2 EXE 和 COM 文件

把文件上传到"虚拟磁盘"后点"运行"：

- MZ 格式的 EXE：处理重定位表，按文件头设置 SS:SP、CS:IP 和内存需求。
- PKLITE 压缩过的 EXE 可以运行（它自己在内存里解压）；其他自解压的压缩工具原理相同，但没有逐个验证过。
- COM 文件：装在 PSP:0100。
- 用到的其他文件（字库、BGI 驱动、数据文件）也要一起上传到虚拟磁盘。

### 10.3 PSP 和环境变量

| PSP 偏移 | 内容 |
|---|---|
| 00h | `INT 20h` |
| 02h | 内存顶端的段地址（A000h） |
| 16h | 父进程 PSP（就是自己） |
| 2Ch | 环境变量块的段地址 |
| 80h | 命令行长度 |
| 81h | 命令行（屏幕右上角的"命令行参数"框），以回车结束 |

环境变量块：`PATH=C:\`、`COMSPEC=C:\COMMAND.COM`，后面是程序的完整路径 `C:\程序名`（程序可以由此找到自己所在的目录）。

**没有设置**：PSP 5Ch/6Ch 处的两个默认 FCB、文件句柄表。

## 11. 从磁盘启动（真 DOS）

在"虚拟磁盘"页的"磁盘映像"部分放入软盘或硬盘的映像文件，点"从 A: 启动"或"从 C: 启动"（可启动的光盘点"从光驱启动"，见 11.2），虚拟 PC 就像开机一样：

1. 把映像的第一个扇区（引导扇区）读到 `0000:7C00`，检查末尾的引导标记 55AAh；
2. 设置 CS:IP = 0000:7C00，SS:SP = 0000:7C00，DL = 启动驱动器号（00h 或 80h），开中断；
3. 从这里开始执行引导扇区的代码。它用 INT 13h 读入磁盘上的操作系统（例如 MS-DOS 的 IO.SYS、MSDOS.SYS），操作系统再接管 INT 21h 等中断。

和 BIOS 一样按 A:、C: 的顺序：选"从 A: 启动"而 A: 没有软盘时，从 C: 启动。

已验证：MS-DOS 6.22 的安装盘可以启动、运行安装程序，在空白硬盘上分区、格式化、复制文件，装好后从 C: 启动；Windows 3.0/3.1（标准模式、386 增强模式）可以安装运行；Windows 95 可以从光盘安装，装好后硬盘、软驱、光驱都用它自带的 32 位驱动（"系统属性 → 性能"显示"按照最优性能配置"）。

**从磁盘启动时和运行普通程序的区别：**

| | 运行汇编程序或 EXE/COM | 从磁盘启动 |
|---|---|---|
| DOS（INT 21h） | 模拟器用 JavaScript 实现（第 6 节） | 磁盘上真的 DOS |
| 文件 | "文件"虚拟磁盘 | 磁盘映像里的 FAT 文件系统 |
| 源码调试 | 有 | 没有（反汇编页可以看正在执行的代码，单步、断点照常可用） |
| 功能键 | F5、F6、F7、F10、F11 是调试快捷键 | DOS 屏幕有焦点时，F1~F12 全部交给虚拟机 |
| "后退" | 默认记录历史，可以退回，内存同时恢复 | 默认不记录历史（记录要多花约 20% 的时间）；勾选工具栏的"记录"后从那一刻开始记录，可以退回，但写进磁盘映像的内容不会撤销 |

**映像里的文件**：磁盘映像那一行的"文件"按钮可以直接查看映像里的 FAT12/FAT16 文件系统：进入子目录、上传电脑上的文件、新建目录、下载、删除，以及把"文件"列表里的全部文件复制进来。

- 文件名自动换成 DOS 的 8.3 格式：太长或者有空格等字符时变成 `NAME~1.EXT` 这样的短名字；
- 保留文件原来的修改日期；
- 写入的目录项和 FAT 表与 DOS 完全兼容，DOS 的 CHKDSK 检查没有错误；
- 虚拟机正在运行从磁盘启动的系统时，修改后不会自动重启。软盘会发出"换过盘"的信号，DOS 自己会重新读目录；硬盘则不行：DOS 在内存里缓存着原来的目录和 FAT 表，可能看不到新文件，按旧的缓存写文件还可能和放进去的文件冲突，所以最好找机会重新启动一次。
- 不支持 FAT32 和长文件名（DOS 6.22 本来也不支持）。

### 11.1 光盘映像（ISO）当作 D: 硬盘

DOS 本身不认识光盘的 ISO9660 文件系统，真机上要装光驱驱动（例如 OAKCDROM.SYS）和 MSCDEX。这里换了一种做法：在 D: 那一行点"上传映像/ISO"选择 .iso 文件，模拟器把光盘的内容**当场变成一块只读的 FAT16 硬盘**。重新启动 DOS 后光盘就是 D:，不用装任何驱动。

- **分区和文件系统是合成的**：0 号扇区是分区表（一个 FAT16 分区，从 63 号扇区开始），引导扇区、FAT 表、目录都由模拟器生成，每个文件占一段连续的簇。文件内容不复制：DOS 读到哪个扇区，就从 ISO 里对应的位置取。
- **不读进内存**：浏览器里保存的是文件本身。放入时只读光盘的卷描述符和目录（通常几百 KB）；文件内容在 DOS 读到时才按 64KB 一块从文件里读出，最近读过的最多缓存 32MB。读文件是异步的，这时 INT 13h 像磁盘在转一样等一会儿（定时器中断照常进行）。刷新页面后从浏览器里恢复，同样不读进内存。
- **文件名**：用光盘主卷描述符里的名字（去掉 `;1`），不合 8.3 格式的换成 `NAME~1.EXT` 这样的短名字。所有文件带只读属性，日期是光盘上的日期。
- **只读**：写扇区返回 03h（写保护），DOS 显示 `Write protect error writing drive D`；剩余空间显示 0（为了凑够 FAT16 最少的 4085 个簇而多出来的簇标成坏簇）。
- **大小**：簇的大小按光盘内容自动选（2KB~32KB），FAT16 最多放 2GB，CD 光盘（700MB 以内）和较小的 DVD 都可以；超过 2GB 时提示放不下。
- 不能从这块盘启动；文件浏览器和"下载"对它不可用。

**关机**：工具栏的"⏻ 关机"让虚拟机停止、屏幕变黑，磁盘映像马上存进浏览器；之后点"重启"重新开机。DOS 的缓冲区和 SMARTDRV 的写缓存里可能还有没写进磁盘的数据，直接关机和真机拔电源一样可能丢失，所以从磁盘启动时会先提醒。更安全的是在 DOS 里运行 SHUTDOWN.COM（文件浏览器里的"放入关机程序 SHUTDOWN.COM"）：它先用 INT 21h AH=0Dh 和 INT 2Fh AX=4A10h 写回缓冲区，再通过 APM 关机。源程序是 `src/dos/shutdown.asm`，在有 APM 的真机上也能用。

注意："文件"列表是给模拟的 DOS 用的，和磁盘映像互不相通；真 DOS 只能看到映像里的文件。

**鼠标驱动 MOUSE.COM**：DOS 启动时会把 INT 20h~3Fh 里自己不用的中断（包括 INT 33h）都指向一条 IRET，于是程序报告"找不到鼠标驱动"。真机上也是这样，所以要在 DOS 启动后加载鼠标驱动。

- 文件浏览器里的"放入鼠标驱动 MOUSE.COM"把它放进当前目录，还可以顺便加到 AUTOEXEC.BAT。
- 它只把 INT 33h 改回 BIOS 里内置的驱动（F000:0198），再复位鼠标；驱动代码在 BIOS 里，不占常规内存。
- `MOUSE /U` 卸载。
- 源程序是 `src/dos/mouse.asm`，用本项目的汇编器汇编。
- 当年的真鼠标驱动（MOUSE.COM、CTMOUSE 等）需要串口鼠标或 PS/2 鼠标硬件，模拟器没有模拟这些硬件，所以装不上。

**磁盘映像的保存**：放入、新建的映像和写进去的内容都保存在浏览器里（IndexedDB），刷新页面后还在；"下载"可以把映像存成文件。换一台电脑或清除浏览器数据后需要重新上传。

**不支持**：硬盘的 LBA 扩展磁盘功能（超过 504MB 的硬盘）、网络、声卡驱动（见第 12 节）。

### 11.2 光驱（ATAPI）

**从光驱启动**："虚拟磁盘"页的"从光驱启动"按钮。支持 El Torito 的软盘模拟方式（Windows 98 安装盘、多数 DOS 启动光盘）：读出光盘里的启动软盘映像（1.2MB、1.44MB 或 2.88MB），这次启动它就是 A:，原来 A: 里的软盘变成 B:（和真的 BIOS 一样，到下次从别的盘启动为止；Ctrl+Alt+Del 重启仍然从光驱启动）。启动软盘可以写，但写的内容不保存。也支持"不模拟"方式（Windows 2000/XP、Linux 的 isolinux）：光盘上的引导程序装入它指定的段（默认 0000:7C00）执行，DL = E0h，这个驱动器号上 INT 13h 提供扩展功能：41h（报告支持，EDD 1.1）、42h（按 LBA 读，每块 2048 字节，直接从光盘映像读）、48h（驱动器参数）、4Bh（光盘启动状态，软盘模拟时 A: 也支持）、00h/01h/44h/47h，43h（写）报告写保护。硬盘模拟方式暂不支持，会给出说明。已验证：Windows XP SP3 安装盘启动到 SETUPLDR：386 档上它报告需要 80486，486 档上报告需要 CPUID 里有 CMPXCHG8B（奔腾的指令）；KNOPPIX 5.1 的 isolinux 显示启动画面并装入 Linux 内核。tools/mkiso.ts 的第 4 个参数可以指定启动软盘，生成可启动的测试光盘（也带路径表，MSCDEX 要用）。

"虚拟磁盘"页的"光驱"一行可以放入光盘映像（.iso），它就是 IDE 第二通道上的一个 ATAPI 光驱（主盘，端口 170h~177h、376h，IRQ15），和真机上的 IDE 光驱一样：

- **DOS**：在 CONFIG.SYS 里装通用的 ATAPI 光驱驱动（例如 `DEVICE=C:\OAKCDROM.SYS /D:MSCD001`），AUTOEXEC.BAT 里运行 MS-DOS 自带的 `MSCDEX /D:MSCD001`，光盘就是一个新的盘符。
- **Windows 95**：用自带的 IDE 和光驱驱动（32 位访问、长文件名）。装 Windows 95 时还没有光驱的话，在控制面板的"添加新硬件"里让它自动检测，会找到"Standard IDE/ESDI Hard Disk Controller"，重新启动后光驱就出现在"我的电脑"里。

已验证：Windows 98 启动盘（通用光驱驱动 + MSCDEX 2.25）、Windows 95 OSR2.5（自带驱动）都能读光盘。
- 光驱是只读的，没有"写盘错误"；光盘可以超过 2GB；换盘、弹出时会通知驱动（"换过盘"），程序也可以用命令弹出光盘。
- 映像不读进内存：读到哪个扇区才从文件里读那一段；还没读出来时光驱报告"忙"，读到后发中断，和真的光驱一样。

支持的 ATA 命令：IDENTIFY PACKET DEVICE（A1h）、PACKET（A0h）、DEVICE RESET（08h），IDENTIFY DEVICE（ECh）被中止并给出 ATAPI 签名（主机据此认出这是光驱）。命令包：TEST UNIT READY、REQUEST SENSE、INQUIRY、START STOP UNIT（弹出）、PREVENT ALLOW、READ CAPACITY、READ(10)、READ(12)、SEEK、READ TOC（格式 0、1，LBA 和 MSF）、READ SUB-CHANNEL、MODE SENSE（能力页）、SET CD SPEED、MECHANISM STATUS、GET EVENT STATUS、GET CONFIGURATION。没有音轨（不能放 CD 音乐）。

### 11.3 软驱控制器

A:、B: 的软盘映像也能经真的软驱控制器读写（Intel 82077AA，端口 3F2h~3F5h、3F7h，IRQ6，DMA 2 号通道）。DOS 自己用 BIOS 的 INT 13h，不经过它；Windows 95（HSFLOP.PDR，32 位访问软盘）、Linux 这样的系统用自己的驱动直接操作控制器。

- 命令：READ DATA、WRITE DATA（含多磁道、DMA 到达终点时正常结束，过了 EOT 报告"磁道末尾"）、READ DELETED、READ TRACK、VERIFY、READ ID、FORMAT TRACK、RECALIBRATE、SEEK（含相对寻道）、SENSE INTERRUPT STATUS、SENSE DRIVE STATUS、SPECIFY（含非 DMA 方式）、CONFIGURE（隐含寻道）、DUMPREG、VERSION（90h，增强型控制器）、PERPENDICULAR MODE、LOCK；其他命令返回"无效命令"。
- 复位（DOR 位 2 或 DSR 位 7）结束时发中断，驱动用 4 次 SENSE INTERRUPT STATUS 读走。
- 命令执行要约 0.5 毫秒的虚拟时间，结果和中断在这之后才出来；驱动器里没有软盘时读写命令不结束（和真的一样，驱动超时后复位控制器）。
- 换盘信号（3F7h 位 7）：放入、换、取出软盘后为 1，寻道（驱动器里有盘时）后清掉。
- 柱面号要和磁头所在的柱面一致，扇区只有 512 字节的；不模拟数据传输率（任何传输率都能读），也没有删除标记的扇区。
- BIOS 的 IRQ6 处理程序（INT 0Eh）和 IBM BIOS 一样在 40:3E 的位 7 记下"中断来过"。A:、B: 固定安装为两台 1.44MB 软驱（CMOS 10h = 44h、14h = 41h），空驱动器也会被操作系统枚举；启动后可插入、换、取出软盘，无须重启。介质容量仍按映像识别。

新建的空白软盘尚未格式化，建议在 DOS 里用 `FORMAT A: /U` 或 `FORMAT B: /U` 格式化（会清除目标软盘上的内容）。MS-DOS 5.x/6.x 的 FORMAT 有已知问题：访问过空软驱后，给未格式化的软盘执行普通 FORMAT 可能仍报“Not ready”，即使 BIOS 读扇区已经成功；重新启动或使用 `/U`（无条件格式化）可绕过，见微软知识库 [Q103547](https://jeffpar.github.io/kbarchive/kb/103/Q103547/)。这与软驱是否已被识别是不同的问题。

兼容性提示：实测的一份 MS-DOS 6.22 `SYS.COM` 在执行 `DISKCOPY A: B:` 后，直接运行 `SYS A:` 会停在环境变量搜索中，而不是等待软驱读写。这份程序的隐式源路径分支错误地再次读取环境段指针，并扫描之前命令留下的内存；相关指令与独立 PKLITE 解压工具的输出一致。若系统文件位于 C: 根目录，可显式指定源路径：`SYS C:\ A:`。已验证此命令生成的系统文件与源文件逐字节一致，且生成的 A 盘能够启动 MS-DOS 6.22；不通过清除客体内存或修改客体指令来规避。

### 11.4 硬盘控制器（IDE）

C:、D: 的硬盘映像经 IDE 第一通道的 ATA 控制器读写（端口 1F0h~1F7h、3F6h，IRQ14；C: 是主盘，D: 是从盘）。BIOS 的 INT 13h 读、写、校验硬盘扇区（AH=02h~04h）也和真的 AT BIOS 一样经过这些端口（ROM 里的 8086 代码，见 src/machine/diskrom.ts），其余 INT 13h 功能在 JavaScript 里完成。Windows 95 的 IDE 驱动启动时会检查这一点（不经过端口时 IOS.LOG 里写"ESDI trap handler not called"，硬盘只能用兼容方式）。Windows 95 的 32 位磁盘驱动（ESDI_506.PDR）、Linux 这样的系统直接操作控制器。装好 Windows 95 后如果"系统属性 → 性能"里还提示硬盘在用"MS-DOS 兼容方式"，在"添加新硬件"里自动检测一次，找到"标准 IDE/ESDI 硬盘控制器"后重新启动。

- 命令：IDENTIFY DEVICE、READ SECTORS、WRITE SECTORS、READ/WRITE MULTIPLE（SET MULTIPLE MODE，每块最多 16 扇区）、READ VERIFY、SEEK、RECALIBRATE、INITIALIZE DEVICE PARAMETERS（改变 CHS 换算用的磁头数、每道扇区数）、EXECUTE DEVICE DIAGNOSTIC、CHECK POWER MODE、SET FEATURES 和电源管理命令（直接完成）；其他命令（包括 DMA 读写、PACKET）中止。
- 地址可以用 CHS 或 LBA（28 位）；默认的 CHS 换算按映像的几何参数（和 INT 13h 一样，最多 1024 柱面 × 16 磁头 × 63 扇区）。
- 只有 PIO 方式；每个命令先报告"忙"约 0.1 毫秒，再置 DRQ（或完成）、发中断（立即发中断的话，Windows 95 的驱动会把它当成多余的中断）。读状态寄存器 1F7h（不是 3F6h）或写新命令时撤销还没被响应的中断请求，和真的 IDE 盘加 8259 一样（光驱的 177h 也是）；软件复位（3F6h 位 2）后寄存器里是 ATA 硬盘的签名。D: 是光盘映像合成的只读盘时写命令被中止，扇区还没从文件里读出来时报告"忙"。
- CMOS 12h、19h/1Ah 里硬盘是类型 47（用户自定义），1Bh~2Ch 是几何参数，2Eh/2Fh 是校验和；BIOS 的 IRQ14 处理程序（INT 76h）在 40:8E 写 FFh。
- Windows 3.1 的 32 位磁盘访问（WDCTRL）不能用：它检查 BIOS 的细节，会报告"interrupt conflicts"。

## 12. 未实现时的行为

| 情况 | 行为 |
|---|---|
| 调用没有实现的中断 | "消息"页提示一次，直接返回，寄存器不变 |
| 没有实现的 INT 10h、16h、1Ah、33h 子功能 | 提示一次，直接返回 |
| 没有实现的 INT 21h 功能 | 提示一次，返回 CF = 1、AX = 1（功能号无效） |
| 访问没有模拟的端口 | 提示一次；读得到 FFh，写入被忽略 |
| 切换到不支持的显示模式 | 提示一次，保持原来的模式 |
| 8087 浮点指令 | 跳过，不提示 |

常见的还没有实现的功能：

- INT 21h（模拟的 DOS，运行汇编程序和 EXE/COM 时用）：4Bh（执行另一个程序）、FCB 方式的文件读写（0Fh~28h 中除 11h、12h、29h 以外）、44h 的其他子功能、5Ah（临时文件）、67h 等；子目录；
- INT 13h 硬盘的扩展功能（LBA，超过 504MB 的硬盘）、INT 15h 的大部分功能（包括 E820h 内存表）；
- 浮点单元（8087/287/387 和 486DX 的浮点部分，见 2.7）；奔腾的指令（RDTSC、CMPXCHG8B、CR4 等），所以 Windows XP 安装盘会报告需要更新的处理器；
- 16MB 以上的内存；
- VESA 高分辨率显示模式；
- 声卡、网卡；从硬盘模拟方式的光盘启动。

## 13. 汇编器支持的语法

汇编器兼容 MASM 6 的一个子集，生成的机器码与 MASM 6.11 逐字节一致（用 `tools/ml-compare.ts` 对照验证）。

| 类别 | 支持 |
|---|---|
| 段定义 | `.MODEL TINY/SMALL` 等简化段定义（`.CODE` `.DATA` `.STACK`），以及 `SEGMENT`/`ENDS`/`ASSUME`/`GROUP` 完整段定义；`ORG`；EXE 和 COM 两种格式 |
| 数据 | `DB` `DW` `DD` `DQ` `DT`、`DUP`、`?`、字符串、`LABEL` |
| 符号 | 标号、变量、`EQU`、`=`、`PROC`/`ENDP`（`NEAR`/`FAR`） |
| 表达式 | `OFFSET` `SEG` `TYPE` `SIZE` `LENGTH` `SIZEOF` `LENGTHOF` `PTR` `SHORT` `HIGH` `LOW`；算术、逻辑、比较运算；段超越 |
| 宏 | `MACRO`/`ENDM`（`LOCAL`、`EXITM`、`&` 拼接）、`REPT`、`IRP`、`IRPC` |
| 条件汇编 | `IF` `IFE` `IFDEF` `IFNDEF` `IFB` `IFNB` `ELSE` `ENDIF` |
| 其他 | `.STARTUP`、`.EXIT`、`END 入口` |
| 指令 | 全部 8086 指令（见第 2 节）；条件跳转超出范围时自动扩展成反向条件跳转 + `JMP`（与 MASM 6 相同） |
| 80186/80286 指令 | 程序开头写 `.186` 或 `.286` 后可用 80186 的 `PUSHA` `POPA` `PUSH 立即数` `IMUL 寄存器, [源,] 立即数` `SHL/SHR… 寄存器或内存, 立即数` `ENTER` `LEAVE` `BOUND` `INS/INSB/INSW` `OUTS/OUTSB/OUTSW`；`.286` 再加 `ARPL` `LAR` `LSL` `VERR` `VERW` `SMSW` `STR` `SLDT` `SGDT` `SIDT`；`.286P` 再加特权指令 `CLTS` `LMSW` `LGDT` `LIDT` `LLDT` `LTR`（划分与 MASM 6.11 相同，编码逐字节一致：tests/ml/i286.asm）。没写这些伪指令时它们仍可当符号名。运行时 CPU 要选 286 或更高，选 8088 时汇编后会提示 |

`MOV 寄存器, 代码标号` 取标号的偏移（和 MASM 一样）。`PUSH SP`、`POP SP` 会给出警告：8086 和 286 上结果不同。常见错误有中文说明，例如"不能把立即数直接送入段寄存器""8086 的移位次数只能是 1 或 CL"。

暂不支持：`STRUC`/`RECORD`、`INCLUDE`、多模块（`EXTRN`/`PUBLIC`）、80386 的 32 位指令（`.386` 按 `.286P` 处理并提示）、8087 指令。
